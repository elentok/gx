## Problem Statement

A Queue agent asks a long question with `gx tickets ask`. On the web UI's ticket page the question sits in a card that scrolls. "Send answer" sits at the bottom of that card, below the scroll. "Resume" is pinned to the bottom of the screen and always visible, so it looks like the main action. The person presses Resume by mistake and the agent restarts from its handoff with no answer. The bug is frequent. The question text also shows twice on the page: once under "THE AGENT ASKS" and again as the body of the answer card.

## Solution

The ticket page stays a normal scrolling page. While a question the person can answer is open (the ticket's detail actions include `answer`, which holds for a question the agent asked itself) it shows one compact card where the question card sits today, below the Agent's notes and above Earlier rounds. While the card shows, the chat is hidden, so nothing repeats the card. The card shows the asker label ("THE AGENT ASKS" or "GX ASKS"), the question title clamped to three lines, and one row of in-flow buttons. "Answer question" is the only main button. "Resume without answering" is secondary, and so is a One-off's Cancel. Nothing is pinned to the screen.

"Answer question" opens a separate page for that one question. The page has a header with "← Ticket" and "Answer question". Its body holds the asker label, the full question, the options, the note and Earlier rounds. "Send answer" is the only button, in a footer outside the scroll, like the Design page's Question sheet. The footer follows the phone keyboard. Resume never sits next to Send answer.

After "Send answer" the person lands on the ticket page. The card reads "Answer sent", shows the question title, the answer and the note when there is one, and has no buttons. Agent's notes stay above it and the chat stays hidden. A collapsed "Show question" toggle on the card opens the full question. If the question was answered elsewhere or changed while the answer page was open, the page shows a banner and the footer's only button is "Back to ticket".

A question that gx asked (zero commits, stranded commits, a background-task gate, an ambiguous base, a blocked pane, a model mismatch) has no Answer verb, so it keeps today's ticket page and its first recovery verb stays main. The "ticket needs answer" push notification opens the answer page directly, and only for a question the person can answer. Every other link still opens the ticket page. When the agent of a ticket with an open question is blocked at a permission prompt, the ticket page also shows the permission card with Approve.

## User Stories

1. As a person with a long queue-agent question, I want "Send answer" always visible on the page where I answer, so that I never have to hunt for it below a scroll.
2. As a person answering a question, I want "Resume without answering" nowhere near "Send answer", so that I cannot press it by accident.
3. As a person on the ticket page with an answerable open question, I want one main button, "Answer question", so that the next step is obvious.
4. As a person on the ticket page, I want every recovery button to be secondary while an answerable question is open, so that none of them looks like the main action.
5. As a person who wants to skip the question, I want "Resume without answering" to stay on the ticket page with that label, so that I can restart the agent knowing it gets no answer.
6. As a person, I want the question text to show once, so that I do not read the same long text twice.
7. As a person on the ticket page, I want a compact card with the asker label and a title clamped to three lines, so that the page stays short and scannable.
8. As a person on a phone, I want a long question title clamped to three lines on the card, so that the buttons stay on screen.
9. As a person, I want the card to sit below the Agent's notes and above Earlier rounds, so that the page keeps its reading order.
10. As a person, I want the Agent's notes to stay on the ticket page and the chat to be hidden while the question card or the "Answer sent" card shows, so that nothing repeats the card and the answer page holds only what I need to answer.
11. As a person answering, I want the answer page to show the full question, its options, a note field and Earlier rounds, so that I have all the context in one place.
12. As a person, I want the answer page to show who asks ("THE AGENT ASKS" or "GX ASKS"), so that I know the source of the question.
13. As a person, I want a "← Ticket" link in the answer page header, so that I can go back without answering.
14. As a person who opened the answer page from the ticket page, I want "← Ticket" and the browser back button to go back one entry to the ticket page, and, when I opened the page by a deep link or a push tap, I want "← Ticket" to replace the entry with the ticket page, so that back never lands on a duplicate and always leaves a ticket page to return to.
15. As a person who just sent an answer, I want the browser back button not to return to the form I answered and not to show the ticket page twice in a row, so that I cannot send into a finished question and back moves on.
16. As a person on a phone, I want the answer page's footer to follow the keyboard, so that "Send answer" stays reachable while I type a note.
17. As a person on a desktop, I want the answer page to use the same layout with a readable column width, so that long lines do not stretch across the screen.
18. As a person who sends an answer, I want to land on the ticket page (one entry back when I came from it, a replaced entry after a deep link or push tap), so that I see the ticket carry on.
19. As a person who has sent an answer, I want the card to read "Answer sent" and show the title, my answer and my note (when I wrote one) with no buttons, so that I know it went through and cannot send twice.
20. As a person who reloads the ticket page after a queued answer (the agent was gone, so the ticket is open again with its answered round), I want the same "Answer sent" card, so that the page tells the same story with or without the page having just sent. A delivered send claims the ticket again, so the page shows no card after a reload. A send that an agent had already finished (adopted) records no answer, so its card also lasts only until a reload, as it does today.
21. As a person whose answer was queued or sent to an agent that had already finished, I want the card to keep its status line, so that I know where the answer went.
22. As a person who picked an option and typed a note, I want my pick and note to survive when I leave the answer page and come back, until I send, the question changes or I reload, so that checking the ticket page costs me nothing.
23. As a person, I want a new question to clear my pick and text but keep my note, including when I open the answer page after the question was replaced while I was on the ticket page, so that a refusal or a swap loses nothing, as the form does today.
24. As a person who opens the answer page after the question was answered elsewhere, I want a banner saying so and a "Back to ticket" button, so that I do not send a second answer.
25. As a person whose question changed while the answer page was open, or whose send was refused as stale, I want a banner saying the question changed and a "Back to ticket" button, so that I read the new question before answering.
26. As a person in the stale state, I want my typed text kept on screen, so that I can copy it.
27. As a person opening the answer page by a link when no question is open, I want the same stale banner, so that a bookmark or old link never shows a dead form.
28. As a person opening the answer page for a ticket that does not exist, I want the "Ticket not found" page, so that I know the link is wrong.
29. As a person whose agent is blocked at a permission prompt while a self-reported question is open, I want "Approve the agent's prompt first, then send again" shown on the answer page with my answer kept, so that I can approve on the ticket page, where the permission card with Approve shows, and come back.
30. As a person on the ticket page with a permission prompt, I want the permission card to stay in the page flow, so that approving works as it does today.
31. As a person who gets the "ticket needs answer" push notification for a question I can answer, I want it to open the answer page, so that I land where I can answer. Only a self-reported pause whose latest round is open counts, for a parent pause and for a conflict child pause.
32. As a person who opens a ticket from any other link, a Queue row or another notification (a repair pause, the recovery escalation, an epic push), I want the ticket page, so that I see the whole ticket first.
33. As a person with a One-off that asks a question, I want Cancel on the ticket page's card as a secondary button, so that I can end the run without it looking like the answer button.
34. As a person with a ticket that has no open question, or only a question gx asked, I want the ticket page unchanged, so that other recovery bars keep working as they do today.
35. As a person on the ticket page with an answerable question when Resume is not offered (the agent is still live), I want the card to show only "Answer question", so that no button is a dead end.
36. As a person using the Design page, I want its question sheet unchanged, so that nothing regresses there.
37. As an agent author, I want Resume to do the same as before, so that only its label and style change.
38. As a person whose ticket is paused on a question that gx asked (`paused-epic/04` Choose base, `paused-epic/06` Retry) or a model mismatch, I want today's page, with the question text in the reading view and the first recovery verb main, so that I never see an "Answer question" button that leads to a page that cannot send.
39. As a person who gets a push for a gx-asked pause, a repair pause, a conflict child pause that no one asked a question in, or the recovery escalation, I want it to open the ticket page, so that no push leads to a dead answer page.
40. As a person who has answered, I want Agent's notes to stay above the "Answer sent" card, the chat hidden, and a collapsed "Show question" toggle on the card, so that the page keeps its reading order and I can still read what was asked.
41. As a person opening the answer page for a ticket whose question is open but cannot be answered here (a gx-asked question), I want the banner "This question is answered on the ticket page." and a "Back to ticket" button, so that I never see a form that cannot send.
42. As a person whose ticket has an open question while its live agent is blocked at a permission prompt, I want the ticket page to show the permission card with Approve next to the question card, so that I can approve there before I answer.
43. As a person who fixed a gx-asked pause with a recovery verb (Choose base, Retry and the others), I want no "Answer sent" card afterwards, so that the page does not claim I answered a question I never answered.

## Implementation Decisions

- **Scope.** The ticket page and a new answer page, for a ticket whose detail actions include `answer` (a self-reported open question, the same rule the server uses to offer the verb). A question that gx asked has an open round but no Answer verb, and the server refuses an answer for it, so its ticket keeps today's page: the question text in the reading view and the first recovery verb main. This holds for `paused-epic/04` and `06`. The layout, the answer page, the "every recovery button secondary" rule and the `/answer/` push apply only when `answer` is offered. The Design page's Question sheet and chat do not change. The new page may reuse the Question sheet's footer-outside-scroll layout and its question rendering.
- **Ticket-page card.** For an answerable question, one compact card replaces both the repeated question under "THE AGENT ASKS" and the sticky answer area. It renders from the ticket detail and one new field, `how` on the answer (see Answered card). The title is the question's summary line, clamped to three lines. The Reading view no longer prints the question body. Agent's notes stay above the card and Earlier rounds below it. The chat is hidden while the card shows, because it repeats the card's title (`roundChat` builds it from the latest round's summary and answer). The permission card shows next to it when the ticket's live agent is blocked at a permission prompt.
- **Buttons on the card.** "Answer question" (main) navigates to the answer page. The recovery buttons the server lists (only Resume appears next to an open question) and a One-off's Cancel render secondary. No recovery button is main while an answerable question is open. Neither the card nor the recovery area is sticky. The recovery bar of every other state is unchanged, including its sticky behaviour.
- **Permission card.** The ticket page shows the permission card (with Approve) whenever the ticket has an open question and its live agent is blocked at a permission prompt. Today the server loads the card only for a claimed ticket or a blocked-pane pause (`server/epics/detail.go`, the rule before `PermissionCard`), so a self-reported open question on a paused ticket shows none. The fix is in that rule: it also loads the card when the latest round is open. `detailActions` already offers Approve from the card. The answerable question's layout renders `PermissionCard` in the page flow above the question card, as `ActionCard` does today.
- **Resume label.** When `answer` is also offered, Resume reads "Resume without answering". The server sets that label in the action's `action_info` (`server/epics/detail.go`, `actionInfo`), so the web UI holds no verb wording. The server's rules for when Resume is offered and what it does do not change.
- **Answer page.** A new page for one ticket's open question. Header: "← Ticket" and "Answer question". Body: asker label, full question (title, body, options with the recommended one marked, links), note, Earlier rounds. Footer outside the scroll: "Send answer", disabled until the answer is ready, using the existing readiness rule (a pick or text, or a note alone for a choice question). Desktop and phone share one layout. The body is a readable column on desktop. On a phone the footer follows the visible area while the keyboard is open. The page uses `useFillHeight` and `useKeyboardOpen` (`webui/src/page/`), as `DetailPage` does. The Question sheet only lays out the scroll body and the footer, so it does not supply this behaviour.
- **Route.** The page has its own route prefix, `/answer/<address>`, a sibling of the ticket route, because a ticket address holds slashes and a sub-path of the ticket route would clash. It can be reloaded, opened in a new tab and shared. The route name is `answer`. It goes into `webui/src/routeNames.ts`, the route-name count test in `webui/src/routes.test.tsx` (21 names become 22) and the server's `webPerfRoutes` (`server/web/webperf.go`), so the server keeps the samples from that route.
- **History.** "Answer question" pushes a history entry, so the stack is [ticket, answer]. When the page was opened from the ticket page, "← Ticket", the browser back button and a successful send each go back one entry, so the stack never holds the ticket twice and back never returns to the answered form. On a deep link, a reload in a new tab or a push tap there is no ticket entry before the answer page, so "← Ticket" and a successful send replace the entry with the ticket page.
- **Draft survival.** The pick and note live in state that survives leaving and returning to the answer page while the browser tab stays open. A send clears them. A new question clears the pick and text and keeps the note. A reload clears all of it. The state may live wherever suits the page. Opening the answer page on a question that replaced the one the form last held starts a fresh form that keeps the note. The stale banner shows only when the question changes while the answer page is open, or when a send is refused as stale.
- **Sending.** The send request, its body and its refusal reasons do not change. A successful send moves to the ticket page (see History) and records the send outcome for the card. A "stale" refusal refetches the ticket and shows the stale state. An "agent not ready" refusal shows the existing message on the answer page above the footer, keeps the typed answer and does not move the person. The permission card is not copied to the answer page.
- **Stale state.** The answer page shows the form only when `detail.actions` includes `answer`. Every other ticket that exists shows a banner and "Back to ticket". The page is stale when the ticket has no open question, or its open question is a different one from the one the form loaded while the page was open. A form opened on an already replaced question is fresh, not stale (see Draft survival). The banner has a wording per case: "This question was answered elsewhere" when it was answered, and "This question changed. Back to ticket to see the new one." when a new one replaced it. The typed text stays. "Send answer" is gone and the footer holds only "Back to ticket". The same rule covers a deep link or reload that finds no open question. A third wording covers an open question with no Answer verb (a gx-asked question): "This question is answered on the ticket page." A ticket that does not exist shows the existing "Ticket not found" state.
- **Answered card.** `wire.DetailAnswer` gets a `how` field, copied from the round's `End.How`. A web recovery verb on a gx-asked pause (Choose base, Retry and the others, with the state check) goes through `resumeAnswered` (`server/ticketops/repair.go`), which logs a `pause.answer` with choice `unpark`, so `latest.answer` is set for it too, and `by` cannot tell the cases apart (the fixture seeds self-reported rounds `By: "gx"`). The card shows only when the latest round has an answer with `how: answer`. A round closed by a recovery verb keeps today's `AnswerResult`. The card reads "Answer sent" and shows the question title, the answer and the answer's note when there is one, with no buttons, and a collapsed "Show question" toggle that renders `latest.text`, like today's `AnswerResult` "Show more". Agent's notes stay above the card and the chat is hidden, as today's answered card hides it. Earlier rounds does not hold the answered round: `detail.rounds` is every round but the latest and carries no text. The card survives a reload only while the ticket is open again with its answered round (`detail.answered`), which holds for a queued answer. A delivered answer claims the ticket again, so its card lasts until a reload. A send that an agent had already finished (adopted) records no answer, so its card also lasts only until a reload. The existing status line for a queued or already-finished send stays on the card when the page knows it. The old "answered" compact card is replaced by this one.
- **Notification.** The "ticket needs answer" push opens the answer page. The pause push is built in the ticket-write module (the pause announcement and its ticket push helper `PushTicket`), with its text from the notify text module. The route is `/answer/<address>` only for a self-reported pause whose latest round is open, the same rule `detailActions` uses to offer `answer`. One helper next to `PushTicket` holds that rule and serves both the parent pause push and the conflict-resolution child pause push (`pushSink.TicketNeedsHuman` in `server/ticketwrite/pause_ticket.go`). Every other push keeps routing to the ticket page: a gx-asked pause, every repair pause, the recovery escalation push (`server/recovery/recovery.go`), an epic push and any Queue or chat link. The tag of the push does not change. The notification tap navigates to the pushed path, so only the pushed path changes. The new prefix goes into the app's route table and its route-name list (see Route).
- **Other recovery verbs** (Retry, Start over, Choose base and the rest) are untouched.
- **Domain terms.** The card and page speak of a Paused ticket's open question (a Pause round's question). The Question sheet and Question card of the glossary belong to the web chat and keep their meaning; the answer page is not a Question sheet, though it reuses its layout.

## Testing Decisions

- **Good tests** check what the person sees and does: which buttons show where, what a click leads to, what a push opens. They do not check component structure, state shapes or route table internals.
- **Seams.** The highest seam is the web UI against a fixture server (a Playwright flow on a Queue ticket with an open question). Playwright cannot open the iOS keyboard, so the phone keyboard rule is covered by shrinking `visualViewport`, as the existing `useKeyboardOpen` tests do. Extend existing flows on the `paused` scenario before adding one. A new flow is justified for the real browser layout: footer outside the scroll, the phone keyboard, the long question at 390px.
- **Vitest** covers the card render (title clamp, buttons, secondary styling, no repeated body, no chat bubble, the permission card beside it), the answer page states (ready and not ready, stale per case, no open question, the third banner for a question with no Answer verb, refusal, answered card with its "Show question" toggle and no card for a recovery-closed round, a claimed ticket after a reload showing no card), the draft survival rule (including a form opened on a replaced question) and the history behaviour with a memory router: a memory-router test for each entry path, from the ticket page (back goes one entry for "← Ticket" and a send) and by a deep link or push tap (both replace the entry with the ticket page). It also covers the card for a gx-asked question, which keeps today's layout. The route-name count test in `routes.test.tsx` covers the new `answer` name. Prior art: the ticket page's action card, answer form, answer result and reading tests, and the ticket screen test.
- **Go tests** cover the push route with `servertest.Pushes`, which records `Path`, in `server/ticketwrite/writer_push_test.go`: a self-reported pause, a gx-asked answer-class pause, a repair pause and a conflict child pause. The recovery escalation push keeps `/t/`. `server/epics/detail_test.go` covers the "Resume without answering" label, set only when `answer` is also offered, `how` on the answer (an answer and a recovery verb on a gx-asked pause), and the permission card on a paused ticket with an open question and a blocked live agent. `server/web` covers the `answer` route name in `webPerfRoutes`. Prior art: the existing server notify tests.
- The Design page's question sheet keeps its own existing tests, unchanged.

## Out of Scope

- Any change to the Design page's Question sheet, Questions view or chat.
- Changing when the server offers Resume or what Resume does.
- A pinned bar, a full-screen question view or any sticky button on the ticket page for an open question. Those layouts were mocked and rejected.
- Moving the answer page's content into "Goto agent". That route shows only while the agent is live and its sheet is for session prompts, not `gx tickets ask` questions.
- Showing Agent's notes or the chat on the answer page.
- Changing other notifications' routes, or the Queue agent's question flow.
- Changing the recovery bars of any other pause state, including a gx-asked question's bar.
- Giving gx-asked questions an Answer verb.

## Self-decided design questions

- **Which pushes open the answer page?** Choice: only a self-reported pause whose latest round is open, the same rule `detailActions` uses to offer `answer`, for the parent and the conflict child pause alike; every other push, the recovery escalation included, keeps the ticket path. Reason: a gx-asked pause has no Answer verb, so the answer page would be dead, and a repair pause has no question to answer.
